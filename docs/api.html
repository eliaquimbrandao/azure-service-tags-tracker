🔌 API

Use Azure service tag IP ranges in your scripts and firewall automation

Everything on this site is plain JSON you can download from a script. It's free, with no key, no sign-up and no rate limit, and it's updated daily from Microsoft's ServiceTags_Public.json. Only need one tag, once? Open it under Service Tags and copy its ranges.

Show examples in:

1. Get the IP ranges of a tag

https://azuretags.egbcorporate.org/data/current.json 
$tags = (Invoke-RestMethod https://azuretags.egbcorporate.org/data/current.json).values
($tags | Where-Object name -ceq "Storage.WestEurope").properties.addressPrefixes
curl -s https://azuretags.egbcorporate.org/data/current.json \
  | jq -r '.values[] | select(.name == "Storage.WestEurope") | .properties.addressPrefixes[]'
import json, urllib.request

data = json.load(urllib.request.urlopen("https://azuretags.egbcorporate.org/data/current.json"))
tags = {t["name"]: t for t in data["values"]}
print("\n".join(tags["Storage.WestEurope"]["properties"]["addressPrefixes"]))

Swap in any tag name. Names are case-sensitive and match Microsoft's, e.g. AzureCloud.eastus.

2. See what changed in the latest update

https://azuretags.egbcorporate.org/data/changes/latest-changes.json 
(Invoke-RestMethod https://azuretags.egbcorporate.org/data/changes/latest-changes.json).changes |
    Select-Object service, added_count, removed_count
curl -s https://azuretags.egbcorporate.org/data/changes/latest-changes.json \
  | jq -r '.changes[] | "\(.service)  +\(.added_count) -\(.removed_count)"'
import json, urllib.request

doc = json.load(urllib.request.urlopen("https://azuretags.egbcorporate.org/data/changes/latest-changes.json"))
for c in doc["changes"]:
    print(c["service"], f"+{c['added_count']} -{c['removed_count']}")

Each change also lists the exact prefixes added and removed, so you never need to compare full snapshots yourself.

3. Get told when something changes

https://azuretags.egbcorporate.org/data/changes/manifest.json 
$newest = (Invoke-RestMethod https://azuretags.egbcorporate.org/data/changes/manifest.json).files |
    Where-Object total_changes -gt 0 | Select-Object -First 1
if ($newest.filename -ne (Get-Content last-seen.txt -ErrorAction SilentlyContinue)) {
    "New Azure update: $($newest.total_changes) tags changed"   # send your alert here
    $newest.filename | Set-Content last-seen.txt
}
newest=$(curl -s https://azuretags.egbcorporate.org/data/changes/manifest.json \
  | jq -r '[.files[] | select(.total_changes > 0)][0].filename')
if [ "$newest" != "$(cat last-seen.txt 2>/dev/null)" ]; then
  echo "New Azure update: $newest"   # send your alert here
  echo "$newest" > last-seen.txt
fi
import json, pathlib, urllib.request

files = json.load(urllib.request.urlopen("https://azuretags.egbcorporate.org/data/changes/manifest.json"))["files"]
newest = next(f for f in files if f["total_changes"])
state = pathlib.Path("last-seen.txt")
if newest["filename"] != (state.read_text() if state.exists() else ""):
    print(f"New Azure update: {newest['total_changes']} tags changed")   # send your alert here
    state.write_text(newest["filename"])

Run it once a day (cron, Task Scheduler, a pipeline or an Azure Function). It alerts only when Microsoft has published something new.

Reference

All files
PathWhat it contains
/data/current.jsonEvery tag and its prefixes right now, in Microsoft's own format. 2.9 MB (≈560 KB gzipped).
/data/changes/latest-changes.jsonWhat changed in the latest update.
/data/changes/manifest.jsonList of every update, newest first, with its date and how many tags changed.
/data/changes/YYYY-MM-DD-changes.jsonWhat changed in the update collected on that date.
/data/history/YYYY-MM-DD.jsonThe full snapshot from that date. Same format as current.json.
/data/summary.jsonTotals and the list of snapshot dates (available_dates).
/data/regions.jsonRegion code to name, e.g. "australiaeast": "Australia East".

Files are gzipped, cached for 10 minutes and can be called from a browser (CORS *). Each has an ETag, so If-None-Match returns 304 Not Modified when nothing changed.

Change file format 
{
  "date": "2026-11-17",
  "total_changes": 147,
  "changes": [
    {
      "type": "ip_changes",
      "service": "AzureArcInfrastructure",
      "region": "",
      "added_prefixes": ["145.133.209.248/30", "145.133.209.252/31"],
      "removed_prefixes": [],
      "added_count": 88,
      "removed_count": 0
    }
  ]
}
  • type is ip_changes when a tag gained or lost prefixes, or service_added / service_removed when a whole tag appeared or disappeared. For those two, the prefixes are in prefixes.
  • Every change also has coverage (address space added and removed) and classification (expansion, contraction, mixed or representation_only).
  • The file also records which Microsoft version was compared (comparison) and where it was downloaded from (metadata). Fields may be added, but existing ones won't be renamed.
Good to know
  • A prefix often belongs to several tags (a service tag, its regional tag and AzureCloud), so it counts once per tag in totals.
  • Dates are when this site collected the data. Microsoft's own date is in each change file's metadata.date_published.
  • Changes from October and November 2025 can't be fully re-checked, and some of their entries have no coverage or classification.
  • Only the Azure Public cloud is tracked, not China or Government.
